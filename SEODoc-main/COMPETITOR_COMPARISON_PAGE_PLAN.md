# 實價登錄查詢工具比較頁計畫

更新日期：2026-07-01

## 建議搜尋意圖

- 實價登錄查詢工具比較
- 實價登錄網站怎麼選
- 官方實價登錄與民間查詢工具差異

建議頁型不是攻擊式「本站 vs 競品」，而是中立的 category comparison。本站使用官方開放資料，應清楚承認官方平台在原始申報查核上的權威性。

## 建議頁面

- Route：`/guides/real-estate-price-tools-comparison/`
- Title：`實價登錄查詢工具比較：官方資料、篩選與地圖怎麼選`
- H1：`實價登錄查詢工具比較`
- 目標篇幅：1,500 字以上，前提是有足夠可驗證資料，不以湊字數為目的。

## 比較欄位

| 欄位 | 驗證方式 |
| --- | --- |
| 資料來源 | 產品官方說明或政府資料頁 |
| 買賣/預售屋/租賃涵蓋 | 實際操作並保存查核日期 |
| 篩選條件 | 產品介面或官方文件 |
| 地圖與圖表 | 實際操作，不推測 |
| 註冊/付費要求 | 官方方案頁；若未公開則寫「未公開」 |
| 原始交易查核 | 連回內政部官方實價查詢 |
| 資料限制揭露 | 各工具公開的方法或限制頁 |

## 發布閘門

以下任一條件不符合，頁面不得發布：

- 每個功能與價格主張都有可開啟的公開來源。
- 價格、方案與功能查核日期在 90 天內。
- 至少由一人實際操作比較對象，不以搜尋摘要代替驗證。
- 公開本站與比較結果的關係，說明本站是其中一個被比較工具。
- 同時列出各工具適合情境與限制，不使用「最好」「最準」等無證據結論。
- 沒有可信評分來源時，不建立 `AggregateRating`。
- 比較對象資料不足時明寫「未公開」，不得猜測。

## 內容結構

1. 40–80 字 answer-first 摘要。
2. 比較方法、日期與利益關係揭露。
3. 功能矩陣。
4. 各工具適合情境與限制。
5. 為何個別交易仍須回官方資料核對。
6. 最後查核日期、來源清單與修訂紀錄。

## Schema 與內鏈

- 使用 `WebPage`、`BreadcrumbList` 與經驗證項目的 `ItemList`。
- 不把政府服務標成本站產品，也不虛構 Product rating。
- 連向 `/methodology/`、`/data-sources/`、`/guides/transaction-records/` 與官方查詢入口。
- 待資料集完成後再加入 `SEO_CONTENT_PAGES`、`NAV_GROUPS`、sitemap 與測試。
